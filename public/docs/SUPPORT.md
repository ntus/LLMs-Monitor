# Support / 不具合・改善要望

## English

The main-header **Support** button prepares a local draft. All diagnostic selections start unchecked. It can include only the chosen app version, service enum, error category and OS family. Preview the exact text and save Markdown; nothing is automatically submitted, uploaded or saved as a report to a server.

After saving, add the expected behavior, actual behavior and minimal reproduction steps. The in-app draft does not collect your balances, account details, usage logs, conversations or screenshots. Manual additions can still contain private information; review them yourself.

The [GitHub issue list](https://github.com/ntus/LLMs-Monitor/issues) belongs to a public repository, confirmed3 November2026. Posts and attachments there can be visible to others. Do not attach API keys, cookies, authentication URLs, account/organization identifiers, invoices, balances, conversation text, private team-bus content or unredacted screenshots. A private intake/support backend is not configured by this guide. If reproduction requires private data, first describe it without that data and ask for an appropriate channel.

## 日本語

1. メイン画面上部の［サポート］を開く。
2. 共有したい定型項目だけ選ぶ。初期状態はすべてOFFです。
3. プレビューを確認して［下書きを保存］。この段階では送信されません。
4. 保存したMarkdownに「期待した動作」「実際の動作」「再現手順」を追記する。
5. 必要ならスクショを手元で切取り・伏字し、アカウント・残高・会話・認証情報がないか確認する。自動的な伏字・画像添付は未実装です。
6. 公開してよい内容だけを、[GitHub Issues](https://github.com/ntus/LLMs-Monitor/issues)で利用者自身が投稿する。アプリからの自動起票・画像送信はありません。

**GitHubは公開の場です。** APIキー・Cookie・認証URL・アカウント／組織ID・請求情報・残高・会話本文・非公開Busの内容は貼らないでください。CSVには利用履歴が含まれるため、原則として合成データや必要最小限の再現条件を使います。秘密情報が必要な場合は送らず、まず非機密の説明で窓口を相談してください。専用の非公開サポート窓口・自動アップロード基盤は未設置です。

## Report template / 報告テンプレート

- App/extension version / 画面・拡張機能の版：
- Browser and OS family / ブラウザーとOS：
- Service / 対象サービス：
- Expected / 期待した動作：
- Actual / 実際の動作：
- Reproduction / 再現手順：
- Frequency / 毎回・ときどき：
- Already checked / 試した確認：
- Optional image / 任意の画像：切取り・伏字確認済みのものだけ

A report is not an authorization to access an account, purchase credits or publish additional data. Requests and fixes are prioritized after reproduction and impact review; no response-time SLA is established here.
